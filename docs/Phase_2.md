# Phase 2 — Database & Migrations

**Goal**: The entire schema becomes reproducible from migrations; the mysqli driver is deleted; all data access goes through Eloquent with prepared statements.

**Effort**: 2 weeks · **Depends on**: Phase 1 · **Unblocks**: Phase 3+ (auth, features)

---

## 1. Objectives

1. Audit the full live schema (`planning.sql` + every inline `CREATE/ALTER TABLE` across 60+ files).
2. Rebuild the schema as ordered Laravel migrations with foreign keys and indexes.
3. Remove the mysqli connection and every raw string-interpolated query.
4. Add seeders for roles, default admin, reference data.

---

## 3. Definition of Done / acceptance criteria

- [x] `php artisan migrate:fresh --seed` reproduces the schema from zero — verified: 74 legacy tables + framework tables, 33 FKs, column parity (only `users` intentionally differs: merged schema)
- [x] Zero `CREATE/ALTER TABLE` statements in any PHP page/controller — grep-gate enforced in CI
- [x] mysqli removed; single PDO/Eloquent path
- [x] Row-count parity report between legacy export and new schema — 74/74 match (data imported into `pgs_app`)
- [x] CI grep-gates active (`bin/grep-gate.sh` + workflow step)

## 4. Risks & mitigations

| Risk | Mitigation |
|---|---|
| Legacy pages still use mysqli during transition | Legacy untouched — it keeps its own `db.php`; the new app uses Eloquent on the same DB (dual-read compatible) |
| Business depends on wide year-column reports | Redesign deferred to module ports (Phases 6–7) with preserved report views |
| Unknown constraints in production data | Snapshot + row parity verified; full checksum mapping in final cutover (Phase 9) |

---

## 5. Exit criteria

Schema reproducible, single DB driver, parity verified. Phases 3+ build on Eloquent only.
